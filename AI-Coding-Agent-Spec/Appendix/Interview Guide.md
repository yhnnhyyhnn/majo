# Interview Guide — 目标用户访谈框架

> **用途**：为 Persona.md 和 Roadmap.md 提供真实用户数据基础。每个问题都直接映射到本规范中需要验证的假设。不是问卷——是半结构化访谈指南，30分钟/人。

## 筛选标准

找 3-5 人，满足：
- 日常写代码（专业开发者，不是学生）
- **正在使用或尝试过至少一种 AI 编码工具**（Copilot / Cursor / Claude Code / OpenCode / Aider 等）
- 覆盖不同经验层级（1-2 人初级，2-3 人资深）和技术栈（前端/后端各至少 1 人）

**不要找**：没接触过任何 AI 编码工具的人、只会用 ChatGPT 复制粘贴代码不算"使用 AI 编码工具"的人。

## 访谈结构（25-30分钟）

### Part 1: 现状（5 min）

1. 你现在主要用什么 AI 编码工具？用了多久？
2. （如果用了多个）什么场景下用哪个？切换的原因是什么？
3. 你的日常工作中，AI 工具帮你做的最多的事是什么？（补全 / 查资料 / 改代码 / 写测试 / Debug / 审代码 / 其他）

**映射假设**：[Market.md](file:///D:/code/test/java-coding-agent/AI-Coding-Agent-Spec/01-Product/Market.md) 的"开发者工具采用阶梯"
- 用户停留在"补全"阶段还是已经到了"Agent"阶段？
- 从补全到 Agent 的转化瓶颈是什么？

### Part 2: 痛点（10 min）——最重要

4. 你现在用的工具，**最让你抓狂的一点**是什么？（只能选一个，不能含糊）

5. （追问上一问的答案）最近一次遇到这个问题是什么时候？当时你是怎么绕过去的？

6. Agent 帮你改代码的时候，你信它吗？什么情况下信，什么情况下不信？

7. 如果你的 Agent **犯了一个错**——不只是写错了代码，而是删了你不需要删的东西、或者跑了一个不该跑的命令——那之后你还会继续用它吗？用了多久才重新建立信任？

**映射假设**：
- [RFC-0015 Permission](file:///D:/code/test/java-coding-agent/AI-Coding-Agent-Spec/03-RFC/RFC-0015%20Permission.md) 的 L2 默认策略——用户觉得"确认太多"还是"确认不够"
- [RFC-0014 Sandbox](file:///D:/code/test/java-coding-agent/AI-Coding-Agent-Spec/03-RFC/RFC-0014%20Sandbox.md) 的安全防线——用户到底遇到过多少"Agent 搞破坏"的真实场景
- [Product Philosophy](file:///D:/code/test/java-coding-agent/AI-Coding-Agent-Spec/00-Vision/Product%20Philosophy.md) "人在回路"——用户真的想要更多控制，还是觉得控制太多是负担？

### Part 3: 选择（10 min）

8. （展示市场主流的定价档位：免费 / $10-20/mo / $100-200/mo）你现在在哪个档位？你觉得这个价格值吗？

9. （展示竞品矩阵中的五个维度——Agent 质量 / 模型灵活性 / 安全默认值 / 生态 / 定价）让你 **只选一个** 作为"最重要的因素"，你选哪个？为什么？

10. 如果现在有一个新产品，它**在 Agent 编排质量和模型灵活性上对标最好的产品，但在安全上默认比所有现有产品都更保守**（删文件永远要确认、命令在沙箱里跑、权限不能静默提升）——你会愿意试一试吗？

**映射假设**：
- [Market.md §5.2](file:///D:/code/test/java-coding-agent/AI-Coding-Agent-Spec/01-Product/Market.md#52-与-prd-p0p1p2-范围的验证) 的"安全默认值是差异化机会"——用户真的在乎吗，还是觉得不安全是 AI 工具的既定现实？
- [KPI.md](file:///D:/code/test/java-coding-agent/AI-Coding-Agent-Spec/01-Product/KPI.md)（大纲）定价验证

### Part 4: 收尾（5 min）

11. 如果让你给理想中的 AI 编码 Agent **写三条硬性要求**，必须是三条，你写什么？

12. 有没有什么是我们没聊到但你觉得很重要的？
