# ADR-0015: Embedding 记忆后端(语义检索 + 词法回退)

日期:2026-09-22 | 状态:已采纳 | 关联:ADR-0008 / ADR-0014 | 上游参照:ReMe embedding recall

## 背景与问题

majo 的长期记忆检索是关键词倒排索引(AND 匹配):查询词必须逐字出现在
记忆文件里才能命中。这导致两类真实失败:

1. **语义鸿沟**——"数据库备份怎么处理的"无法召回只写了"每晚 02:00
   转储"的记忆(词面不相交);
2. **跨语言盲区**——中文记忆对英文查询零召回。

上游 QwenPaw 的 ReMe 用 embedding 召回解决此类问题,但其实现绑定
Python 生态与 ReMe 配置面板。

## 决策

新增 `embedding` 记忆后端(ADR-0008 SPI 的第三实现):

1. **索引结构**——`memory/.index-embedding.json`:按段落合并分块
   (~700 字符,单段超 1200 硬切),每块存 `{source, text, vector}`;
   索引头部带 `model`,模型名变化即触发重建。
2. **查询**——查询文本先嵌入,与全部块做余弦相似度,阈值 0.15 以下
   丢弃,按相似度排序返回。查询必须用与索引相同的模型嵌入(维度与
   语义空间是模型属性)——实现按 endpoint 分组比较。
3. **双路回退**(分层退化,不丢记忆):
   - 端点不可解析 → 继承的 KeywordMemoryBackend 词法检索直接生效;
   - 端点存在但调用失败 → 同样回退词法;与词法索引共存,词法索引
     始终同步维护,任一路径都可用。
4. **模型配置来源**(按优先级):
   agent 运行配置 `reme_light_memory_config.embedding.{model,
   base_url, api_key}` → agent 生效聊天连接 → 全局 Settings。
   仅 model 为必需;base_url 缺省为 OpenAI 官方端点。
5. **端点协议**——OpenAI 兼容 `POST /embeddings`,分批(32/请求),
   兼容 OpenAI、vLLM、Ollama OpenAI 层等自托管服务。
6. **防腐**:模型变更自动重建;`/memory forget` 的 rebuildForPath
   同步刷新语义索引;remember 的每日记事追加后增量重嵌该文件。

## 备选与取舍

- **本地嵌入库(ONNX/CLI)**:零网络依赖但引入数百 MB 运行时;
  桌面包体积与交付是 majo 核心约束,放弃。
- **仅词法加强(同义词/词干)**:不解决跨语言盲区,治标。
- **整文件单向量**:文件过长时召回粒度太粗,采用分块。

## 后果

- 正面:语义召回 + 跨语言;词法回退保证永不失忆;配置缺省即可用
  (沿用聊天凭据);模型切换自动重建。
- 负面/限制:嵌入调用有网络与费用(每文件一次增量、每次索引重建
  一次全量);向量精度 float 存 JSON(体积可控:百级块 × 1536 维
  ≈ 数 MB);相似度阈值 0.15 为经验值,可能漏掉弱相关。
- 兼容:keyword 与 summary 后端行为不变;`memory_manager_backend
  = "embedding"` 显式启用,未配置时默认 keyword 不变。

## 验证

EmbeddingMemoryBackendTest(6 用例,假嵌入客户端确定性向量):语义
排序命中、remember 后每日记事可召回、嵌入失败词法回退、分块合并与
硬切、模型名变更触发重建、未配置工作区词法回退。
