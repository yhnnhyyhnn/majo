# Vision

## 一句话愿景

**让 AI Agent 成为开发者默认的编码方式——而不是又一个自动补全插件。**

## 为什么现在

软件工程正在经历第三次工具范式转移：

1. **IDE 时代（1990s-2010s）**：语法高亮、静态分析、重构工具把"写正确代码"变得容易。
2. **补全时代（2018-2022）**：Copilot 类工具把"写下一行代码"变得快。
3. **Agent 时代（2023-）**：Agent 把"完成一个任务"变成可能——从"我打字，AI 补全"变成"我描述意图，AI 规划并执行"。

Cursor、Claude Code、OpenCode、OpenHands、Codex 的出现证明了这个转移是真实的、正在发生的，不是概念验证。开发者已经在生产环境里让 Agent 读代码、改代码、跑测试、提 PR。

我们要做的，是在这个已经被验证的范式里，做出一个**功能对标、体验扎实**的产品——不追求发明新范式，追求把已知正确的东西做扎实。

## 五年后的样子

如果这个产品成功，五年后它应该具备：

- **意图到实现的可靠转化**：开发者描述"做什么"，Agent 能可靠地规划"怎么做"并执行，出错率和返工率显著低于人工编码 + 传统补全组合。
- **深度上下文理解**：不是"读取当前打开的文件"，而是理解整个代码库的架构、约定、历史决策，像一个资深工程师一样做决策。
- **可信的自主性梯度**：从"每一步都要我确认"到"我可以放心让它跑一个完整任务再来看结果"，用户可以按信任程度调节自主性，而不是非黑即白。
- **多形态协同**：本地 CLI 处理即时任务，云端 Agent 处理长耗时任务，两者共享上下文和记忆，用户不需要在不同工具间重复解释背景。
- **生态而非孤岛**：通过 MCP 等协议接入外部工具和数据源，成为开发者工作流的枢纽，而不是又一个信息孤岛。

## 我们不做什么

明确边界和明确目标同样重要：

- **不做通用 AI 助手**。这是编码 Agent，不是聊天机器人、不是文档助手、不是通用任务自动化平台。所有能力围绕"帮助完成软件工程任务"展开。
- **不追求 100% 自主**。人在回路（human-in-the-loop）是核心设计前提，不是过渡阶段的妥协。见 [Product Philosophy](Product%20Philosophy.md)。
- **现阶段不追求差异化定位**。先把 Cursor/Claude Code/OpenCode 已经验证有效的能力做扎实、做对，再谈差异化。见 [Mission](Mission.md)。

## 与本规范其他文档的关系

Vision 是最高层的"北极星"，不直接约束具体设计决策，但所有下游文档（PRD、Architecture、RFC）在出现设计分歧时，应回到这里检验方向是否一致。
