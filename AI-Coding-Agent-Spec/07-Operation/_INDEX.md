# 07-Operation — 目录说明

> **状态：🚧 待展开** — 本目录当前仅有此说明文件，尚未产出具体内容。**本目录部分内容（定价、商业化细节）对应 [PRD.md](../01-Product/PRD.md) 中标注为待后续迭代的开放问题，非 v1.0 首要交付内容。**

## 本目录的定位

07-Operation 覆盖产品上线后的运营侧工作——定价策略、增长获客、客户成功、社区运营、竞品动态跟踪。这是产品从"能用"到"能持续经营"的关键一环。

## 计划包含的文件

- `Pricing.md` — 定价策略（订阅制 vs 用量计费 vs 混合，呼应 [PRD.md §7 开放问题](../01-Product/PRD.md#7-开放问题)）
- `Growth.md` — 增长与获客策略，目标渠道
- `Customer Success.md` — 客户成功流程，尤其是首次使用旅程的引导设计（对应 [User Journey.md](../01-Product/User%20Journey.md) 首次使用旅程）
- `Community.md` — 社区运营（开源策略、开发者关系）
- `Competitive Tracking.md` — 竞品动态持续跟踪机制（Cursor/Claude Code/OpenCode/OpenHands/Codex 的版本更新与策略变化）

## 与已完成章节的关联

- 定价策略需要与 [KPI.md](../01-Product/KPI.md) 中的商业化指标协同确定
- 客户成功流程直接承接 [User Journey.md](../01-Product/User%20Journey.md) 的首次使用与信任建立旅程设计
- 竞品动态跟踪是 [Market.md](../01-Product/Market.md) 一次性竞品分析的持续化延伸

## 启动这个目录写作的前置条件

- 定价策略需要等 v1.0 核心功能交付并完成小范围内测后，基于真实用户付费意愿反馈再定稿，避免闭门造车定价
- 竞品动态跟踪机制应该在产品开发阶段就以轻量形式启动（持续关注，而非等到上线前才开始），但正式的运营流程文档待临近上线阶段再完整撰写
