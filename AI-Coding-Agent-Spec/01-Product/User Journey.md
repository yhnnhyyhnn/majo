# User Journey — 用户旅程

> **状态：🚧 大纲占位** — 本文档尚未完整撰写，以下是该章节应回答的核心问题清单和结构大纲，供后续迭代填充。

## 本章节应回答的核心问题

1. 用户从"第一次安装/运行"到"完成第一个成功任务"之间的完整路径是什么？哪些环节最容易流失？
2. 首次使用时，产品如何在不吓退用户的前提下建立"这个 Agent 值得信任"的初始信任？
3. 从"每步都要确认"到"愿意授权自主执行"的信任升级过程，用户会经历哪些关键节点？
4. 当 Agent 犯错时（[Product Philosophy](../00-Vision/Product%20Philosophy.md)"失败要显性、要可恢复"），用户的实际恢复路径是怎样的，体验是否顺畅？
5. 长期使用后，用户的工作流会发生什么变化（是完全替代手写代码，还是与手写代码交替进行）？
6. 团队场景下，一个开发者配置的 Agent 偏好/自主性设置是否需要与团队其他成员共享或隔离？

## 建议大纲结构

- **1. 首次使用旅程**：安装 → 配置模型 Provider → 首次任务 → 首次 diff 确认 → 首次成功体验
- **2. 日常使用旅程**：典型一天内用户与 Agent 交互的完整流程（对应 [PRD.md](PRD.md) 场景 A-D）
- **3. 信任建立旅程**：从默认最低自主性到用户主动调高自主性的转折点分析
- **4. 错误恢复旅程**：Agent 出错 → 用户发现 → 定位问题 → 回退/修正 → 重新授权的完整路径
- **5. 团队采用旅程**（P1+）：个人试用 → 团队内推荐 → 团队级配置统一
- **6. 流失与召回场景**：用户可能在哪些环节放弃使用，如何设计挽回机制
