# KPI — 指标体系

> **状态：🚧 大纲占位** — 本文档尚未完整撰写，以下是该章节应回答的核心问题清单和结构大纲，供后续迭代填充。

## 本章节应回答的核心问题

1. [PRD.md §6](PRD.md#6-验收标准总纲) 提到的"任务一次性完成率""对比基线定量对比"等指标，具体的度量口径和计算方式是什么？
2. 哪些指标是产品质量指标（任务完成率、diff 接受率），哪些是商业指标（留存、付费转化），两类指标如何避免互相干扰优化方向？
3. "用户对 Agent 的信任度"这种主观感受，是否存在可量化的代理指标（例如"自主性级别设置从低到高的迁移率"）？
4. 安全红线类指标（沙箱逃逸率、误操作率）的监控和告警阈值是什么？
5. Context Engine 的检索质量（[RFC-0002 §10](../03-RFC/RFC-0002%20Context%20Engine.md#10-验收标准) 提到的 Recall ≥ 80%）如何持续监控，而不仅是发布前一次性测试？
6. 北极星指标（North Star Metric）是什么——候选包括"每周完成的任务数""diff 接受率""次周留存率"？

## 建议大纲结构

- **1. 北极星指标定义与理由**
- **2. 产品质量指标**：任务完成率、diff 接受率（按 hunk 粒度）、平均任务耗时、错误恢复成功率
- **3. 增长与留存指标**：激活率、次周/次月留存、渠道获客对比
- **4. 商业化指标**：付费转化率、ARPU、订阅续费率（依赖 [07-Operation](../07-Operation/_INDEX.md) 定价策略先确定）
- **5. 安全与可靠性指标**：沙箱隔离有效性、Permission 误判率、Session 恢复成功率
- **6. 指标看板与监控**：与 [RFC-0016 Telemetry](../03-RFC/RFC-0016%20Telemetry.md) 的数据采集能力对应
- **7. 指标反作弊设计**：防止团队为了指标好看而做出损害真实用户价值的优化（呼应 [Design Principles](../00-Vision/Design%20Principles.md) 原则 10"可验证优先于感觉好用"的反面警示）
